# Product UX Optimizer

Read the repository’s product design standards and platform guidance. Honor requested scope and established access, consent, billing and release boundaries.

1. **Audit the journey.** Define the user’s job, starting state, and meaningful result. Walk first-time and returning paths. Count required taps, distinct surfaces and decisions, excluding typing from taps but counting OS/provider handoffs separately. Compare the same endpoints. Explain necessary friction; do not claim unmeasured timing or conversion lift.
2. **Make the next action obvious.** Give each screen one purpose and one primary action. Remove repeated copy and controls, use progressive disclosure, favor native interactions, and preserve a clear return path and user state across layouts. Request permissions in context. Use safe defaults for reversible choices; keep explicit consent, purchase confirmation and safeguards for irreversible actions.
3. **Deliver value early.** Seek a meaningful result within 60 seconds where feasible. Start with a real free task or a clearly labeled local sample before identity or billing where technically safe. Do not treat a displayed screen as a completed result or bypass auth and privacy boundaries.
4. **Make monetization an informed choice.** Keep free paths usable. Trigger upgrades only on voluntary paid-feature discovery, a real limit, or a meaningful request for more. State the specific outcome, free versus paid, exact localized total, frequency, renewal and verified trial terms beside one purchase action. Include obvious dismissal (if free use exists), restore, management, terms, privacy, and cancellation/error/pending/success states. No fabricated urgency, hidden price, repeated interruption, fake eligibility, or default charge. When exploring paywalls, compare outcome, demonstration and personalized-context concepts; recommend one without assuming a conversion lift.
5. **Measure responsibly.** Define eligible cohort, denominator, observation window, dedupe, authoritative purchase events and guardrails. Never collect raw activity, location, health, messages, or account/payment identifiers for this optimization. Do not enable telemetry, experiments, release, or price changes without authorization.
6. **Verify and hand off.** Use editable Figma components/prototypes when requested, actual device or simulator checks where available, and platform accessibility checks for large text, navigation, assistive tech, appearance and resize. Show specific before/after evidence. Name which claims were observed, inferred, or not checked, and record exceptions with a reason and owner.
