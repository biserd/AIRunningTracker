# Native UX follow-through backlog

[Original audit](UX-AUDIT.md) · [Implementation review](UX-IMPLEMENTATION-REVIEW.md) · [Editable design](https://www.figma.com/design/EyKSVPyHnIfRqWAXS5CGdG)

This is a delta to the completed audit. Priority reflects task risk and reach; effort is relative: S = one surface, M = several surfaces or targeted regression coverage, L = navigation/data-contract change plus device QA.

| ID · priority · effort | Observed issue | Change and expected benefit | Affected surfaces and acceptance |
|---|---|---|---|
| R1 · P0 · M | The map and secondary metrics compete with time. Mark Lap is in the scrollable content even when visible initially. The timer excludes pauses. The finish form's inputs are view-scoped, not draft-scoped. | Make active time the primary metric and put Pause/Lap/Finish in a predictable area. Reset inputs when the draft identity changes. | Run, recording, save. Start remains one tap. A successful pause changes the label and disables lap; finish never discards; keep paused retains same-draft inputs. The next draft starts clean. Main controls meet 44 pt. |
| C1 · P0 · M | Native Coach drops the server's structured plan proposal and supplies only description plus generic buttons. The concept promises two editable days even though the existing move endpoint proposes one workout. | Show actual supported dates/duration/constraints, make Apply and Keep explicit, and remove the preview when the server marks it stale or uncertain. Expected to prevent stale confirmation and confusion about scope. | Coach chat/voice results. Review never writes before approval. Keep performs no write. Drafts without structured fields still show their authoritative description. A 409 or 503 does not offer the same action again. |
| A1 · P0 · M | Initial setup leads with provider accounts even though free recording does not need one. | Put Continue to Run above an optional connector disclosure. Lower search and choice cost without creating a new required screen. | Verified-email setup, optional connections. One tap lands in Run without a billing or authorization prompt. Both connectors remain available; Garmin consent is still required before its authorization. |
| B1 · P1 · M | Separate purchase CTAs start the Apple sheet immediately; trial copy assumes seven days and unavailable plans have no retry. | Select a plan, then one Continue action. Render Apple price and introductory period beside the action. Keep restore, cancellation, terms and management visible. | Premium in Coach/Plan/Account. No selection or trial terms are invented; no Apple sheet on option tap. Pending disables a duplicate purchase; confirmed transaction uses existing account-token and server checks. Exercise real StoreKit eligible/ineligible and pending cases before release. |
| P1 · P1 · M | Heatmap targets can be 28 pt, activity selection stores an outdated object after refresh, and insights clear until each new response. | 44-pt dated cells, explicit selected outline and readable metric scope, retain the same account's last data on refresh errors. | Progress, calendar, nested run detail. Both 12-week and 6-month ranges remain. Selecting a populated day opens the correct activity. Never show a prior runner's data. Garmin remains a separate private view. |
| I1 · P1 · L | iPad top-level sidebar exists, but adding a permanent third column risks a narrow pane and lost detail state across resize. | Implemented: width-adaptive history/detail surfaces in Run and Progress share stable selection across layout changes. | Wide history has side-by-side detail; narrow and accessibility sizes use the existing back path. Automated checks cover changes in available content width. Real window resize, keyboard focus and VoiceOver still require device QA. |
| P2 · P2 · M | Some surfaces use gradients and opaque/glass nesting; the Figma chart example suggests total and history data share the same scope. | Use named semantic colors, opaque content panels, native segmented controls. Keep all-source totals separate from the eligibility-limited chart and score rather than relabeling data. | Run, Coach and Progress. Dark and light semantic pairs measured. VoiceOver can identify period, source, value, and selected day. Do not infer cross-provider coverage. |
| M1 · P3 · S | Chat auto-scroll uses an unconditional animation; additional motion in recording would distract. | Honor Reduce Motion for user-visible chat scrolling. Defer other transitions until usability has been checked. | Coach. New review is discoverable; with Reduce Motion it appears without animated scroll. No change to voice/audio behavior. |

Changes to backend schemas, tracking, purchase products, subscription prices, GPS logic, and release processes are not part of this iteration. No activation, conversion or retention lift is assumed.
